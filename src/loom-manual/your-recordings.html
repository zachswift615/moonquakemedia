Everything you play is a file on your own disk, in a folder you can open, copy and back up.

The songs folder

LOOM keeps your songs in:

~/Music/LOOM

That is the LOOM folder inside the Music folder in your home folder. LOOM creates it the first time it needs it.

Each song is a folder rather than a single file. The folder is named after the song and ends in .loom:

~/Music/LOOM/Take 5.loom

Characters a filename cannot hold become hyphens, so a song you named Take 5 / reprise is saved as Take-5---reprise.loom. The name you typed is kept inside the song, spaces and all, and the Open song list shows that name.

What is inside a song

Take 5.loom/ session.json takes/ take-00000000000000000042.wav take-00000000000000000042.peaks

  • session.json holds the song: the tempo, the arrangement, the track settings, and which take each track is holding.
  • takes/ holds the audio. Every recorded pass is one file.
  • .peaks files are drawing data derived from the take beside them. They are not recordings.

Each take is a WAV file: 32-bit float, two channels, at the sample rate your interface was running at when you recorded it. Every LOOM track records two channels; see Track strips. Both channels hold the same audio unless you panned the track's inputs apart on the mixer's INPUTS bank, in which case the take is a true stereo file. Any audio application can open one. LOOM writes the samples you played without re-rendering them, so a take you copy out of this folder is what came out of your instrument.

When the audio reaches the disk

A take is written when the pass that made it closes. While you play, the recording is held in memory. When you close the loop, LOOM writes the file on a separate thread. The file appears whole or not at all: LOOM writes the audio beside its final name and moves it into place only when it is complete.

You do not need to save for your audio to reach the disk. ⌘S writes session.json. It does not record or re-encode your audio, and on the song you have open it does not copy it either. Only Save As… copies audio; see Saving a copy of a song.

A pass you are still playing is not on disk. If LOOM stops running before a pass closes, that pass is lost. Every take already written survives.

Saving and quitting both tidy the folder, and they do it cautiously. A take is removed only when a newer take on the same track has replaced it, and that newer take is named in the saved song and present in the folder. Anything the song still names stays, and a track's newest recording is never removed, because nothing has replaced it.

If the song names a recording the folder does not hold, or the folder holds one no track claims, LOOM says so on the notice line when you save, so you do not first find out when you open the song.

Saving a copy of a song

Save As… (⇧⌘S) with a new name gives you a second song, and both songs are complete. LOOM copies the recorded audio into the new song's folder and leaves the folder you saved from unchanged. You can open either song afterwards and its tracks play.

The copy is real audio rather than a link to the first song's files, so from then on the two songs are independent. Deleting one, or tidying its folder, does not affect the other.

Because the save copies the audio, saving a copy takes slightly longer than an ordinary save. For songs of the size you make in practice, you will not notice the difference.

Naming a song for the first time is different, because only one song is involved. See A song you have not named.

A song you have not named

LOOM records into a folder from the moment you start playing, even before you name the song. An unnamed song gets its own folder beside your named songs. The folder is named Untitled followed by the date and time you started the song:

~/Music/LOOM/Untitled-20260827-214103.loom

The stamp is YYYYMMDD-HHMMSS in your local time, so unnamed songs sort in the order you played them. If a second unnamed song starts in the same second, its folder gets -2 on the end, and a third gets -3, so two unnamed songs never share a folder.

Your audio is in that folder. When you save the song under a name, LOOM moves your recordings into the named song's folder. It moves them rather than copying them, and never re-encodes them. Saving a song that already has a name under a new name works differently; see Saving a copy of a song.

Unnamed folders stay where they are until you remove them. They appear in the Open song list, so you can reopen one and give it a name.

What LOOM opens when you start it

LOOM opens the song you were in when you last quit. Every time it saves, it records which song folder that is, and it reads that back at the next launch.

LOOM also keeps a recovery copy of the session, outside your songs folder:

~/Library/Application Support/LOOM/LastSession.loom

The recovery copy is a full copy of the session and is rewritten every time LOOM saves. You do not open it yourself. LOOM uses it in one case: if your song's folder has been moved, renamed or deleted since you last quit, LOOM opens the recovery copy instead and the notice line names the file that is missing. LOOM keeps the song's name, so your next save writes the song back where it belongs.

If the recovery copy itself cannot be read, LOOM opens the song your last save recorded, says on the notice line that the last session could not be read, and writes a fresh recovery copy at the next save. A recovery copy written by a newer version of LOOM is left alone, and the notice line says that instead.

The recovery copy belongs to this Mac. Copying ~/Music/LOOM to another Mac copies your songs but not this file, and the other Mac does not need it.

Backing up

Copy ~/Music/LOOM. The folder is self-contained: songs, settings and audio. A copy of it opens on another Mac with LOOM installed.

To keep one song, copy its .loom folder. To keep only the audio, copy the .wav files inside its takes folder. They are ordinary audio files and need nothing from LOOM to play.

Make a copy before a show. Two gestures inside LOOM delete audio, and neither asks a second time:

  • CLEAR and ALL CLEAR discard a track's material. UNDO does not put it back.
  • Replacing a saved song deletes that song's whole folder, recorded takes included. See Replace a saved song.

When the folder cannot be written

If LOOM cannot open the takes folder when a session starts, the session still runs and the notice line says so, naming the folder and the reason:

recorded audio will NOT be saved: the takes folder in "…" could not be opened

You can play and loop in that state. Nothing is written to disk until the folder is reachable, so fix the folder before you record a take you want to keep.

Performance recordings

RECORD on the transport records your whole performance as separate files, one for each stream you ticked in File ▸ Record Setup…. See RECORD and Record setup. These recordings are separate from your songs and their takes, and nothing goes into the song's folder.

Each recording is a folder in:

~/Music/LOOM/Recordings

The folder is named for the song and the date, for example Take 5 2026-09-19. A second recording of the same song on the same day is Take 5 2026-09-19 (2).

Take 5 2026-09-19/ Track 1.wav Track 2.wav Instrument 1.wav CUE.wav FX 1.wav Main Mix.wav Group 1.wav Markers.txt

Each file is named for the stream it holds: a loop track by its position, an instrument track by its number, a bus by the name the mixer gives it, and a group by its number. Groups are numbered, not named, so a group's file keeps its name for as long as the group exists; see Groups: the ROUTING page.

Each WAV file is 32-bit float, two channels, at your interface's sample rate. All the files in one recording start at the same moment and stay in sync, so you can drop the folder into any audio application and line the files up at zero.

A file larger than 4 GB continues in a second file. At 48 kHz a stereo file reaches that size after about three hours. The next part has a name like Track 1 (2).wav, and recording carries on.

If LOOM stops unexpectedly, the files are still readable. While it records, LOOM updates each file's length every few seconds, so a file is readable up to the last update.

Markers.txt

Each recording has one Markers.txt, a plain text file you can open in any text editor. Its first line names the recording and its sample rate. After that, each line records one gap:

gap at 01:12.004 (frame 3456192), 10.667 ms (512 frames)

A gap is a moment when the disk could not keep up and LOOM dropped a block of audio. LOOM fills the gap with silence in every file at once, so the files stay in sync. The line gives the gap's time from the start of the recording, its position in samples, and its length. A gap at the very end of a recording is not filled; its line says at the end, not filled.

LOOM writes each line when the gap happens, so the file is complete even if LOOM stops unexpectedly. A recording with no gaps has the line no gaps.
